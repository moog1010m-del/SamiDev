# إصلاح الانتظار والتحقق من الحسابات

هذا التصحيح تقني فقط: لا يغير ملفات الشخصيات أو البرومبت أو الإعدادات أو الصلاحيات. فرع `review/chat-bots-behavior` لا يُدمج تلقائيًا بهذا التصحيح؛ عند نقله إلى ذلك الفرع احتفظ بإعداداته ومحتوى الشخصيات كما هي.

الرسالة الواردة أثناء التهدئة تبقى معلقة حتى انتهاء التهدئة، وتندمج الرسائل المتتابعة في سياق واحد ويُرد على آخرها. لا تلغي زيادة أعضاء الروم الرد الجاري. يبقى إلغاء الرد القديم عند وصول رسالة أحدث.

## غياب الحسابات من الإدارة

نسخ أحدث المستودع في مجلد فحص مستقل لا يحدث السيرفر الذي يعمل من مجلد آخر. تحقق من مسار العملية المصغية على المنفذ ومن commit في مجلدها الفعلي. حدث الكود مع حفظ قاعدة PostgreSQL والتخزين الدائم والإعدادات المحلية، ثم أعد تشغيل الخدمة الصحيحة. لا تستبدل قاعدة البيانات ولا تحذف Redis أو ملفات الجلسات.

في أحدث واجهة الإدارة يوجد زر **اللاعبون الآليون** ثم **تجهيز 50 حسابًا لكل روم**. التجهيز يتم عبر API محمية بصلاحيات الإدارة ويضيف الناقص فقط. مجرد رفع الكود لا ينشئ الحسابات على قاعدة السيرفر.

يمكن للوكيل استخدام جلسة مالك صالحة من البيئة المحلية، دون طباعة قيمتها، في المتغير `PLAZR_BOT_ADMIN_SESSION`:

```sh
python experiments/chat-bots/provision_roster.py --base-url http://127.0.0.1:56648
python experiments/chat-bots/provision_roster.py --base-url http://127.0.0.1:56648 --apply
```

الأول يفحص فقط، والثاني يجهز الناقص حتى 50 في كل واحدة من المساحات الأربع. يعرض العدد الفعلي والمتصل وحالة عامل اللعب. لا يغير أسماء الحسابات الموجودة أو بروفايلاتها أو صلاحياتها، ولا يكرر الحسابات عند إعادة التنفيذ. الحسابات الموجودة المعطلة تظل معطلة؛ تفعيلها اختيار مستقل من لوحة الإدارة.

هذه حسابات اللاعبين المدارة، وليست تشغيل 200 اتصال Gemini. تشغيل محادثات API يتم بخدمة الشات المستقلة، وتشغيل ضربات البلياردو يحتاج العامل الموضح في `experiments/pool-bots/README_AR.md`.

بعد النشر تحقق من العدد من API، ومن ظهور الحسابات في الرومات، ومن حالة عامل اللعب؛ لا تعتمد على نجاح Git وحده. لا حاجة إلى أي تغيير في محرك ألعاب البشر.
