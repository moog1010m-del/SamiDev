منع تكرار الحساب لا يكشف شخصًا يستخدم حسابات مختلفة، ولا يمنع التواطؤ بين لاعبين. تحتاج هذه الحالات سياسة مستقلة ومراقبة نتائج إذا أردت معالجتها.

## تقوية إعدادات التشغيل

- تسجيل الدخول للعب أصبح مفعّلًا افتراضيًا، ويُلزم به وضع الإنتاج.
- GameHost المحلي يستمع على loopback افتراضيًا. النشر أو الاستماع خارج loopback يتطلب مفتاح خدمة خاصًا بطول 32 حرفًا على الأقل، مع رفض قيم الأمثلة المعروفة.
- `start_dev.py` يولد مفتاحًا عشوائيًا مشتركًا للخدمتين عند عدم تحديد مفتاح.
- تُرفض الرسالة التي تجمع تقرير الحالة وحركة لعب في حزمة واحدة.
- فحص الحساب في Redis موضوع داخل عملية Lua الذرية، بما فيها فحص تكرار الحساب عند دخول متزامن.

## التحقق المنفذ

النتائج الفعلية محفوظة في `GAME_SECURITY_TEST_REPORT.json` و`ORIGINAL_ASSETS_TEST_REPORT.json`.

- اختبارات المحرك تغطي إعدادات الكيرم الخمسة للاعبين وأربعة لاعبين: تزوير نقاط ومواقع وملكة، إعادة الحركة، تجاوز الدور، الحقول الداخلية، واستعادة حالة السيرفر.
- اختبار تصادم حقيقي يحتسب 20 نقطة لقرص دخل الجيب، ويُبقي الدور لصاحب الضربة.
- اختبار عميلين بالمحرك الأصلي يثبت تطابق الأدوار والنقاط والتسلسل بعد ضربتين. هذا اختبار محرك بلا عرض رسومي.
- اختبارات HTTP/WebSocket بحسابات مسجلة تثبت رفض أخذ المقعد، وتكرار الحساب، وحركات المشاهد وإعادة الضربة؛ والتقرير المزور لا ينهي المباراة.
- اختبارات إعادة الاتصال، المهلة والاستسلام الآلي، خصوصية أوراق Crazy8، وحركات كرة الطاولة والأصول بقيت ناجحة.

تشغيل التحقق:

```bash
python tests/verify_game_security.py
python tests/verify_original_release.py
```

لم يتوفر Redis فعلي هنا. يمكن تشغيل اختبارات ملكية المقعد عليه باستخدام `SAMIDEV_TEST_REDIS_URL` ثم `python tests/game_security_store.py`؛ يستخدم الاختبار نطاق مفاتيح عشوائيًا ويحذف مفاتيحه بعده.

## تطبيق النسخة وحدود الفحص

فك ZIP في مجلد جديد، وانقل إعداداتك الخاصة بصورة آمنة، ثم أعد تشغيل Gateway وGameHost بعد انتهاء المباريات الجارية. لا تُضمَّن الأسرار في الملفات العامة. ضع المفتاح الخاص نفسه في `SAMIDEV_GAMEHOST_SERVICE_KEY` على جميع الخدمات، واستبدل قيمة المثال قبل تشغيل الإنتاج. تشغيل التطوير المعتاد: `python start_dev.py`.

توجد زيادة في عمل السيرفر لأنه ينفذ فيزياء الكيرم؛ لكل ضربة حد أقصى لخطوات المحاكاة. لم ننفذ اختبار ضغط للإنتاج أو اختبار هاتف فعلي في هذه المراجعة. اختبارات Redis والتوزيع بين عدة سيرفرات ما زالت مطلوبة قبل اعتماد نشر كبير. النتائج تغطي المسارات المختبرة، ولا تمثل ضمانًا بخلو كامل المشروع من الثغرات.
