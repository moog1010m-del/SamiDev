# ضغط شات الإنتاج

يشغّل `production_chat_load.py` افتراضيًا 150 حسابًا مستقلًا في كل مساحة من المجلس والساحة والديوان والنخبة (600 حساب). الرسائل عشوائية كل 40–80 ثانية لكل حساب، مع سقف مشترك 20 طلب REST بالثانية. الانتظار بين الرسائل مقصود لاحترام حدود الروم والإرسال. لا يغيّر حدود الإدارة أو حماية الـIP. يجمع وصول SSE لكل مستقبِل حسب معرف الرسالة، ويحسب الاسترجاع باللقطات، والفقد عند النهاية، وتكرار أحداث message وتسرب الرسائل بين المساحات. لا يحفظ نصوص أو هويات رسائل المستخدمين الحقيقيين في التقرير.

من مجلد `SamiDev_Platform` على خادم Docker Compose، بعد توفير الملف المرفق:

```bash
docker compose cp tools/production_chat_load.py gateway1:/app/tools/production_chat_load.py
docker compose exec -T gateway1 python /app/tools/production_chat_load.py --prepare --sessions /tmp/chat-load-sessions.json
docker compose exec -T gateway1 python /app/tools/production_chat_load.py --url https://YOUR-DOMAIN --sessions /tmp/chat-load-sessions.json --duration 600 --report /tmp/chat-load-report.json
docker compose cp gateway1:/tmp/chat-load-report.json ./chat-load-report.json
```

استبدل `https://YOUR-DOMAIN` بأصل الموقع بدون `/platform/`. التهيئة تنشئ 600 حساب ضيف تجريبيًا في مخزن الإنتاج الموجود بالكونتينر، ولا تحذفها بعد الاختبار. لا تكرر التهيئة: الملف الموجود يمنع الكتابة عليه؛ أعد استخدامه ما دامت الجلسات صالحة. ملف الجلسات سري بصلاحيات 600؛ لا ترفعه للمستودع أو ترسله مع التقرير. الاستعداد لا يعدّل حسابات اللاعبين الموجودة أو قواعد الغرف. الرسائل `[LOAD TEST ...]` تظهر فعلًا للاعبين وتبقى ضمن سياسة احتفاظ الشات الطبيعية.

مدة 600 ثانية تبدأ بعد اكتمال توصيل كل الحسابات، ثم مهلة 20 ثانية لاستقبال آخر الرسائل. يتوقف تلقائيًا بعد المدة؛ Ctrl+C ينهي الاتصالات وينفذ محاولة مغادرة المساحات. إذا كانت سعة مساحة لا تسمح بدخول الحسابات مع اللاعبين الموجودين، يظهر فشل الدخول بدل تغيير الحد تلقائيًا. فشل الطلب/تحديد المعدل موثق في counters؛ الطلب غير المؤكد لا يعتبر مرفوضًا أو مقبولًا تلقائيًا. عند failure أو completed=false لا تعتبر التجربة اختبارًا ناجحًا لـ600 لاعب.

النجاح: completed=true، عدد clientsWithInitialSnapshot يساوي 600، وجود accepted_messages، missingAtEnd=0، وعدم وجود unconfirmed_sends أو cross_room_deliveries أو رفض HTTP. افحص أيضًا p95 وp99 وstream_errors وduplicate_live_events. زمن الوصول محسوب من محاولة الإرسال ويشمل الانتظار في محدد الطلبات المحلي؛ ليس زمن الشبكة وحده. المقصود فحص API/SSE الفعليين، وليس رسم Canvas/DOM أو Flutter أو قياس CPU/ذاكرة السيرفر. تشغيل المولد داخل gateway1 يشارك موارد الباك إند؛ للتقييم المستقل انقل السكربت وملف الجلسات بشكل آمن إلى جهاز آخر مثبت عليه Python وaiohttp وشغّل أمر --url هناك.

التحقق قبل التسليم: تشغيل وظيفي محلي بأربع مساحات وثمانية حسابات فعلية وجلسات مستقلة، مع إرسال عبر HTTP واستقبال SSE والتحقق من التقرير والمغادرة. لم يُشغّل ضغط الإنتاج من بيئة Codex.
