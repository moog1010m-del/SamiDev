# SamiDev V25 + Crazy 8 — ثلاث ألعاب في منصة واحدة

دمج الكيرم وكرة الطاولة وكريزي 8 في منصة واحدة: حسابات ومحفظة وغرف ودعوات ومشاهدة مشتركة، وباك إند واحد يوجّه كل غرفة إلى محرك لعبتها. هذه نسخة دمج وتجربة محلية؛ لم تُنشر على سيرفر خارجي.

## التشغيل على Windows

1. فك ملف ZIP كاملًا في مجلد جديد، ثم افتح مجلد SamiDev_Platform_V25.
2. شغّل START_SAMIDEV.bat الموجود معه. START_WINDOWS_DEV.bat يستدعي المشغّل نفسه.
3. انتظر ظهور رسالة «SamiDev V25: served UI verified» وفتح المتصفح تلقائيًا. يظهر V25 أعلى الواجهة.
4. سجّل الدخول أو أنشئ حسابًا، ثم ادخل إحدى المساحات. تظهر الألعاب الثلاث: **الكيرم** و**كرة الطاولة** و**كريزي 8**. اختر كريزي 8، وحدد عدد اللاعبين والإعدادات، ثم اضغط «إنشاء مباراة كريزي 8».

المتطلبات: Python 3.12 وNode.js 22 أو أحدث. ملف BAT يجهّز بيئة Python ويثبّت المتطلبات؛ أول إعداد يحتاج إنترنت. اترك نافذة التشغيل مفتوحة أثناء اللعب. الوضع الافتراضي يستخدم Redis وPostgreSQL ويتطلب إعداد متغيرات الاتصال. وضع الذاكرة اختياري للتجربة فقط ويُفقد عند الإيقاف.

للتشغيل اليدوي:

```bash
python -m pip install -r backend/requirements.txt
python start_dev.py
```

للفحص دون فتح المتصفح، مع إيقاف الخدمات بعد الفحص:

```bash
python start_dev.py --storage memory --check
```

المشغّل يتحقق من ملفات الواجهة المحلية ثم يقارنها بالملفات التي يرجعها السيرفر عبر HTTP؛ يرفض الملفات المختلطة أو الواجهة القديمة قبل فتح المتصفح. يفتح رابط /platform/ الخاص بالعملية الجديدة مباشرة.

## إصلاح V25

- اختيار اللعبة بأزرار ظاهرة في المساحة ونافذة إنشاء المباراة، مع اسم اللعبة على زر التأكيد.
- علامة V25 على شاشة الدخول والمنصة ونافذة الإنشاء لتحديد الإصدار المعروض.
- روابط CSS وJavaScript تحمل بصمة المحتوى، والواجهة تُرسل دون تخزين مؤقت.
- نافذة الإنشاء قابلة للتمرير في الشاشات القصيرة.
- تضمين ملف BAT داخل الحزمة، وإظهار خطأ واضح عند نقص الملفات أو اختلافها.
- تقديم واجهة المنصة من الباك إند نفسه في إعداد Nginx، لتجنب أخذها من نسخة مختلفة في المجلد المركّب.

سبب المشكلة على جهاز المستخدم غير مثبت؛ لم يتوفر اتصال بالسيرفر الذي عرض الواجهة السابقة. الإصلاح يزيل الاعتماد على التأكد من الملفات فقط، ويتحقق من الواجهة المقدّمة بالفعل.

## ما تغير

- استبدال مراجع الهوية القديمة في الكود بـSamiDev، بما فيها الجسر العام والدوال المرتبطة به. أسماء دوال اللعب العامة بقيت على معناها لتجنب التعارضات.
- إضافة gameId لإعدادات الغرفة وسجل ألعاب في الباك إند والواجهة، واختيار اللعبة من نافذة إنشاء الغرفة.
- ثلاثة محركات داخل خدمة GameHost نفسها مع حالة مستقلة لكل غرفة. الحسابات والجلسات والخدمات الاجتماعية مشتركة.
- تحويل الانضمام والمشاهدة إلى صفحة اللعبة الصحيحة مع الاحتفاظ برمز إعادة الاتصال داخل جلسة المتصفح.
- توزيع فرق كرة الطاولة 0 و1 ضد 2 و3، والكيرم 0 و2 ضد 1 و3، مع تصحيح اختيار الخصوم في التقييم.
- تنفيذ فيزياء كرة الطاولة والأهداف على السيرفر وحفظ حالة مكتملة بعد التسديدة، ورفض استبدال المواقع من العميل.
- التحقق من الدور والأرقام وشكل الحركة قبل تشغيل المنطق؛ يمنع المسارات المعروفة لتجاوز الدور وتغيير موضع الضارب بحركة مرفوضة في الكيرم.
- إبقاء الغرفة قابلة لإعادة محاولة البدء عند تعطل GameHost مؤقتًا.

## فروق كرة الطاولة

الفريقان الأحمر والأزرق والملعب الافتراضي متاحون بالصور المرفقة. صور الدول والفرق والملاعب المدفوعة غير موجودة في المصدر المرفق، لذلك استُبعدت خياراتها من القوائم.

في الأونلاين تبقى نتيجة التمريرة الفيزيائية بدون التحريك التلقائي اللاحق للكرة والقطع نحو اللاعب. المصدر كان يحركها بالعميل ويرسل الإحداثيات إلى السيرفر. احتساب التمريرات والأهداف مستمر، لكن هذا التحريك التلقائي معطل لمنع تبديل المواقع من العميل.

## اختبارات V25

راجع V25_TEST_REPORT.json للنتائج وحدود الاختبار. نجحت الاختبارات التالية:

- تشغيل الباك إند وGameHost والتحقق من بصمات ملفات الواجهة عبر HTTP.
- رفض واجهة قديمة حتى عندما يعيد /api/build رقم الإصدار الصحيح، ورفض مجلد خلطت فيه ملفات قديمة وجديدة.
- تشغيل HTML وJavaScript الفعليين في LinkeDOM، مع حساب وتذاكر حقيقية من الباك إند، ودخول مساحة والضغط على أزرار اللعبتين والتأكد من ظهور إعداداتهما والتوجيه الصحيح.
- اختبارات HTTP/WebSocket: تسجيل ودخول، مباريات اللعبتين، حركات وأدوار، مشاهدة وإعادة اتصال ودعوات واستعادة حالة كرة الطاولة.

```bash
python start_dev.py --storage memory --check
python tests/start_dev_ui_check.py
npm install --prefix tests
python tests/platform_ui_http.py
python tests/multigame_ws.py
node tests/multigame_routing.js
```

LinkeDOM يفحص عناصر الصفحة ومعالجات الأحداث ولا يرسم واجهة متصفح. لم يتوفر اختبار بصري ناجح لـChromium في هذه البيئة، ولم يُشغّل BAT على Windows فعليًا، ولم يُختبر إعداد Nginx/Docker المعدّل. المنطق الذي يستدعيه المشغّل اختُبر على Linux. تقارير V24 والإصدارات الأقدم تاريخية وليست نتائج تشغيل V25. لم تحدث عملية نشر أو ترحيل بيانات.

## ملاحظات الأمان المتبقية

الدمج لا يغلق تقرير الأمان بالكامل. المسارات التالية من المراجعة السابقة ما زالت تحتاج إصلاحًا واختبارًا قبل الإطلاق العام:

| المرجع | المسار المتبقي |
| --- | --- |
| F04 | سباق تحديث sequence أثناء resync وإضافة الحركة إلى سجل التخزين |
| F05 | استعادة الكيرم من snapshot أقدم مع تجاهل الحركات اللاحقة في GameHost |
| F07 | الحظر لا يبطل اتصال WebSocket المفتوح فورًا |
| F08 | رمز إعادة الاتصال غير مربوط بإحكام بهوية الحساب صاحب المقعد |
| F09 | إمكانية جلوس الحساب نفسه في مقاعد متقابلة واستغلال المكافآت |
| F10 | فحص كلمة المرور المتزامن يحجب حلقة أحداث الباك إند مؤقتًا |

تحسنت المسارات المحددة في F01 وF02 وF03 بالتحقق المسبق من الحركات، وأُصلحت قابلية إعادة محاولة البدء في F06. لم تُنفذ مراجعة أمنية شاملة جديدة لكل المسارات.

## الخدمات والبصمات

docker-compose.yml يربط الألعاب الثلاث بنفس المنصة وقاعدة Redis ونقطة Nginx. يحتفظ بالتوزيع الموجود: ثلاث بوابات وثلاث عمليات GameHost، ويمكن تشغيلها كلها على جهاز واحد. كل GameHost يدعم الألعاب الثلاث؛ لا يلزم سيرفر مستقل لكل لعبة. مفاتيح الخدمة والدومين وHTTPS تُضبط كما في إعدادات المشروع. لم تحدث عملية نشر أو ترحيل بيانات.

بعد تعديل ملفات الواجهة أو حزم اللعب عمدًا، أعد توليد البصمات بهذا الترتيب:

```bash
python tools/update_ui_build.py
python tools/update_game_integrity.py
```

game/samidev-integrity.json يثبت بصمة كل حزمة. ملفات attestation.json الجديدة جرد SHA-256 غير موقّع باسم SamiDev، وليست توقيعات ناشر خارجي.
