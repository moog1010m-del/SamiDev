# إضافة بلازر أونو إلى SamiDev

تم دمج اللعبة المرفقة في المشروع، ثم تنظيف هويتها وتحديث ألوان السبرايت شيت وظهر الورقة؛ راجع `CRAZY8_REFRESH_AR.md`. التعديل محلي داخل هذه الحزمة ولم يُنشر على استضافة خارجية.

## التشغيل

1. فك الحزمة كاملة في مجلد جديد. لا تخلطها مع ملفات إصدار قديم.
2. على Windows شغّل `START_SAMIDEV.bat`. يدويًا: ثبّت متطلبات `backend/requirements.txt` ثم شغّل `python start_dev.py` باستخدام Python 3.12 وNode.js 22 أو أحدث.
3. سجّل الدخول، ثم ادخل إحدى المساحات واختر **بلازر أونو**.
4. اختر عدد اللاعبين ونوع المباراة والأوراق الخاصة، ثم أنشئ الغرفة.
5. يدخل الآخرون من قائمة الغرف أو الدعوة. يبدأ عدّ الدور بعد اكتمال تحميل اللعبة لدى الجميع.

وضع التطوير يستخدم الذاكرة؛ الحسابات والغرف فيه لا تبقى بعد إيقاف السيرفر. إعداد Redis وDocker الموجود في المشروع باقٍ للاستخدام في النشر.

## الربط المنفذ

- تسجيل `crazy8` في كتالوج الواجهة والباك إند وGameHost وبصمات الملفات ومشغّل المشروع.
- دعم غرف 2 و3 و4 و6 لاعبين وغرف فريقين 2 ضد 2؛ إعداد `seats` الأصلي يحدد السعة.
- استخدام الحسابات والجلسات والدعوات والدردشة والمشاهدة وإعادة الاتصال ونظام النتائج والمكافآت الموجود.
- تشغيل منطق اللعبة نفسه على GameHost: توزيع الأوراق، التحقق من ملكية الورقة والدور، اللون، الأوراق الخاصة، السحب، الانسحاب والنتيجة.
- رفض حركات التصحيح الداخلي والأشكال غير المسموحة والأرقام غير الصحيحة والتكرار، مع تجاهل الحالات المرسلة من المتصفح.
- حالة السيرفر الكاملة محفوظة داخليًا. المتصفح يتلقى حالة مخصصة لمقعده عبر التسلسل الأصلي `serialize(seat)`؛ كومة السحب وأوراق الخصوم مخفية، مع احترام كشف الأوراق المسموح بقواعد اللعبة وظهور أوراق زميل الفريق.
- المشاهد يتلقى حالة المقعد `-1`. لا يحق له إرسال حركات.
- حفظ النسخ المخصصة مع نقطة استعادة السيرفر، للحفاظ على خصوصية الأوراق أثناء إعادة الاتصال أو انقطاع GameHost.
- استخدام المؤقت الأصلي للسحب التلقائي والانسحاب بسبب عدم النشاط؛ تجميده أثناء تحميل العملاء ثم تفعيله عند بدء المباراة.
- تكييف الخروج والتقييم وأسماء الغرف مع اللعب الفردي والفرق.

## الإعدادات

| الحقل | القيم |
| --- | --- |
| `gameId` | `crazy8` |
| `seats` | 0: لاعبان، 1: ثلاثة، 2: أربعة، 3: ستة، 4: فريقان 2 ضد 2 |
| `live` | 1: مباشر، 0: تناوب الأدوار |
| `special` | 0: أساسية، 1: جميع الأوراق الخاصة، 2: الدرع، 3: كشف الأوراق، 4: الأحمر، 5: الأزرق |

## الاختبارات والحدود

النتائج المنفذة فعليًا موجودة في `CRAZY8_TEST_REPORT.json`. اختبارات التكامل تستخدم HTTP/WebSocket حقيقيًا مع GameHost، وباك إند في وضع الذاكرة وحسابات اختبار مؤقتة.

- 60 مباراة مكتملة على السيرفر: جميع تراكيب أنماط المقاعد الخمسة × نوعي المؤقت × مجموعات الأوراق الست.
- فحص الحالات الخاصة لكل مقعد، إخفاء الكومة، رفض الحركات غير الصالحة والتكرار، حفظ الأوراق واسترجاعها، السحب التلقائي وتجميد المؤقت.
- دخول بحسابات، دعوات، مشاهدة، سحب، إعادة اتصال، محاولة استبدال الحالة من العميل، انقطاع السيرفر وإعادة إنشاء المحرك، والانسحاب في جميع أنماط المقاعد.
- فحص جسر واجهة اللعبة الأصلي وتحريك الأوراق محليًا وعن بعد ومطابقة حالة العميل للسيرفر. WebGL والصوت محاكيان في هذا الفحص؛ لم تُنفذ معاينة بصرية فعلية لغياب متصفح مثبت في بيئة الاختبار.
- إعادة اختبارات منطق وشبكة الكيرم وكرة الطاولة للتأكد من عدم كسرهما.
- لم يُختبر Redis/Docker أو تشغيل إنتاجي متعدد الخوادم في هذه البيئة.

ملف بلازر أونو المرفق لا يحتوي جميع الأصوات والموسيقى ولا صور متجر الأوراق الاختيارية. عطلت مسارات الأصوات والموسيقى المفقودة وأزيل الكتالوج غير المتاح ومدخل المتجر القديم. الأصول الأساسية للأوراق والواجهة مرفقة، مع ظهر الورقة الجديد. لم تُضف ملفات بديلة من الإنترنت. اللعبة الجديدة متاحة عبر غرف الأونلاين؛ اللعب المحلي بالتناوب على الجهاز غير مفعّل لها.

## إعادة التحقق

من داخل مجلد المشروع:

```bash
node tests/crazy8_runtime.js
python tests/crazy8_ws.py
node tests/browser_multigame_smoke.js crazy8 online
node tests/multigame_routing.js crazy8
node tests/multigame_runtime.js
python tests/multigame_ws.py
python start_dev.py --check
```

بعد تعديل ملفات الواجهة أو حزمة `main.js` عمدًا، حدّث سجلات البناء والبصمات:

```bash
python tools/update_ui_build.py
python tools/update_game_integrity.py
```
