# عرض المنتج والدخول إلى اللعبة

نافذة المنتج تستخدم مساحة رسم محددة، ثم معاينة منفصلة للاسم، فالاسم والوصف، ومنطقة سعر وشراء ثابتة. المحتوى الداخلي قابل للتمرير عند قصر الشاشة دون تكبير الصورة أو تغطية زر الشراء. تعتمد التصميمات والألوان والمقتنيات الخاصة بـ SamiDev، ولا تضيف إرسال هدايا أو عمليات شراء غير موجودة.

## الدخول

كان تجهيز الأصول يبدأ من حدث تعيين الغرفة، ثم ينتظر تنزيل الصور والنصوص قبل طلب main.js، وكانت واجهة الإطار والشات تظهران قبل الرسم. الآن:

- يبدأ تجهيز الموارد بعد تحميل browser-runtime، أثناء تحميل بقية وحدات الواجهة، ويتشارك الانتظار وبدء المباراة محاولة الموارد نفسها.
- يُطلب main.js مسبقًا بنفس عنوان البصمة المستخدم لاحقًا، ويُنفّذ بعد جاهزية الموارد؛ لا تغيير لفيزياء المحرك أو التحقق أو أوامر اللعب.
- يجري الاتصال وتأكيد صلاحيات الغرفة بالتوازي؛ لا تهيئة للمباراة ولا إرسال حركات قبل التعيين المعتمد.
- تبقى واجهة المنصة ظاهرة وغير قابلة للتفاعل أثناء التجهيز، ويظهر إطار اللعبة عند أول drawFrame ناجح. تظهر رسالة الخطأ عند فشل بدء اللعبة، ولا تُخفى خلف الإطار الشفاف.
- يتوقف التنزيل الاستباقي للخلفية عند بدء الدخول نفسه. لا تُنشأ ألعاب خفية، ولا مقابس إضافية، ولا مشهد انتظار منفصل.

`__samidevStartup` يحتوي توقيت runtime/assetsStart/roomAssigned/assetsReady/logicReady/firstFrame بالنسبة لبدء صفحة اللعبة، دون معلومات حساب أو محادثات. سرعة الجهاز، فك الصور وتهيئة WebGL وزمن الشبكة ما زالت تؤثر؛ التخزين المؤقت لا يلغي هذه المراحل.

التحقق: `store_product_layout_browser.py` لعنصر badge_shard الذي ظهر متضخمًا، على الكمبيوتر والهاتف والشاشة القصيرة والثيمين؛ `game_startup_browser.py` لفتحين متتاليين ورصد عدم إظهار الإطار قبل أول رسم؛ `spa_game_host_browser.py` للألعاب الأربع والانضمام والمشاهدة والاستعادة والخروج.
