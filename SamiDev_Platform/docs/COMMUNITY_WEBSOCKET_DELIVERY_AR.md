# قناة شات المساحات في الويب — 18 أكتوبر 2026

استمر المستخدم بملاحظة تأخير شات المساحات رغم نجاح SSE في القياس المحلي.
لم يثبت سبب تأخير النسخة العامة: رابط التانل رفض طلبات هذه البيئة سابقًا.
هذا التغيير يقدم مسار WebSocket مستقلًا للمساحات، مع قياس القناة الفعلية،
ولا يدعي أن اختبارًا محليًا حدد سبب عطل الرابط العام أو أثبت زواله هناك.

## السلوك

- يستخدم الويب `/ws/community/{community_id}` للإرسال والاستقبال. يثبت
  السيرفر الهوية من جلسة الدخول، ويحفظ الرسالة قبل بثها أو تأكيدها.
- بقيت صلاحيات المساحة والكتم والحظر وملكية الملصقات وحدود الإرسال مشتركة
  مع HTTP. لا تُقبل هوية أو صلاحية أو رابط أصل يقدمه العميل داخل الرسالة.
  يلزم المصدر المسموح وHTTPS في الإنتاج، ويُعاد التحقق من الجلسة عند الإرسال
  ودوريًا أثناء الاستقبال. الاتصالات محدودة وطوابير البث محدودة.
- عند انقطاع المقبس يُعاد الاتصال وتُقرأ لقطة التاريخ. عند ضياع تأكيد رسالة
  محفوظة، تستخدم المحاولة الاحتياطية عبر HTTP نفس `clientMessageId`، فيرجع
  السيرفر نفس الرسالة. لا يتكرر صفها في PostgreSQL أو فقاعتها عند المستلم.
- بقي SSE للتوافق عند تعذر ترقية الاتصال، والتاريخ الدوري للاسترجاع. هذه
  مسارات احتياطية ويُظهر التقرير استخدامها؛ لا يُوصف polling بأنه تسليم فوري.
- شات المباراة ومساره `/ws` وملفات `samidev-network.js` و`chat-ui.js` ومحركات
  الألعاب الأربعة لم تتغير. اشتراك Flutter الأصلي ما زال SSE؛ هذه الجولة
  تخص شات الويب، وحزمة الأصول المشتركة أعيدت مزامنتها فقط.

## معرفة المسار على النسخة المنشورة

بعد دخول المساحة، يمكن نسخ تقرير الاتصال من وحدة المتصفح:

```js
JSON.stringify(window.SamiDevCommunityLive.report(), null, 2)
```

يعرض `transport` إن كان الاتصال `websocket` أو `sse-fallback` أو منفصلًا،
ووقت آخر إطار، وزمن تأكيد الرسائل وذهاب ورجوع ping. تسجل كل رسالة جديدة
مصدر ظهورها: إطار مباشر، لقطة استعادة أو تاريخ دوري. عمر الرسالة تقديري بعد
تصحيح فرق الساعة باستخدام ping؛ لا يغني عن زمن الرحلة المقاس من ساعة العميل.
يتضمن التقرير معرف بوابة عشوائيًا وحالة اشتراك Redis وعدد أخطاء النشر المحلية.
لا يتضمن نصوص الرسائل أو ملفات الدخول أو رموز الجلسة. السجل محدود بآخر 60 حدثًا.
تُسجل أعطال نشر/اشتراك Redis في السيرفر بتحذير محدود التكرار بدل إخفائها كليًا.

يلزم نشر backend والأصول معًا وتحميل إعداد Nginx الجديد الذي يمرر Upgrade
لمسار `/ws/community/`. في خادم Python المباشر يكفي مسار التطبيق الجديد.
السحب دون إعادة تشغيل الخدمة لا يسجل مسارًا جديدًا في خادم يعمل بالفعل.
يمكن مقارنة `/api/build` وبصمة `platform/community-live.js` مع البناء المنشور؛
يجب توحيد بوابات النسخة، خصوصًا عند تحديث أكثر من بوابة.

## التحقق المحلي

- ستة اختبارات HTTP/WebSocket فعلية: المصدر والجلسة وHTTPS، سقف الاتصالات،
  منع انتحال الهوية، عزل الرومات، الكتم والحظر وإبطال جلسة مفتوحة، ملكية
  الملصقات، حد الإرسال المشترك، تعارض معرّف الرسالة، وتحرير الموارد.
- PostgreSQL وRedis وبوابتان مستقلتان ومتصفحان: 64 رسالة في المساحات الأربع،
  مع حجب SSE وطلبات إرسال HTTP والتاريخ الدوري. وسيط الظهور 29 مللي ثانية،
  وp95 يساوي 140، والأقصى 500. هذه قياسات محلية وليست قياسات التانل العام.
- عبر Nginx مؤقت بإعداد المشروع نفسه وأصول عامة من البناء الحالي: 64 رسالة
  عبر البوابتين، مع نفس الحجب. الوسيط 25 مللي ثانية وp95 يساوي 37 والأقصى 53.
  لم تظهر أخطاء JavaScript/CSP أو استجابات فشل شبكي في التشغيل الناجح.
- توافق SSE: ثماني رسائل، الوسيط 33 وp95 يساوي 55 مللي ثانية.
- إسقاط تأكيد المرسل ونسخته الراجعة عمدًا: رسالتان، إعادة التأكيد عبر نفس
  المعرّف بعد مهلة ست ثوانٍ، وصف SQL وفقاعة واحدة لكل رسالة. أقصى استعادة
  ظهور عند مستقبل يعيد الاتصال 448 مللي ثانية. لا يطبق حد الحالة المستقرة
  على تجربة الانقطاع المتعمد؛ حُدد للاستعادة حد مستقل 1500 مللي ثانية.
- تجربة تعطيل البثين: ثماني رسائل، وسيط 2200 وp95 يساوي 2623 مللي ثانية؛
  توضح الفرق بين التاريخ الدوري والوصول المباشر، ولا تمثل أداء القناة الجديدة.
- فُحص تطابق 680 أصلًا في حزمة Flutter و39 بصمة في بناء الويب.
- نجح اختبار إنشاء الألعاب الأربع والانضمام والعودة للمساحة، مع بقاء مشهد
  اللعبة واتصالها وعقد الاستسلام والتقييم كما كانت. نجح اختبار liveness
  الحالي لشبكة القيم أيضًا. لا يعادل ذلك اختبارًا جديدًا للفيزياء أو مباراة كاملة.

الأوامر من `SamiDev_Platform`، مع قاعدة PostgreSQL وRedis مخصصتين للاختبار
على localhost، وPlaywright/Chromium مثبتين:

```sh
python tests/community_socket_regression.py
python tests/postgres_community_latency.py
SAMIDEV_CHAT_TEST_NGINX=1 python tests/postgres_community_latency.py
node tests/network_liveness_regression.js
python tests/spa_game_host_browser.py
```

يحتاج اختبار PostgreSQL إلى `SAMIDEV_TEST_DATABASE_URL` و
`SAMIDEV_TEST_REDIS_URL`، ومسار `SAMIDEV_PLAYWRIGHT_MODULE`، واختبار Nginx
إلى Docker وصورة `nginx:1.27-alpine` متاحة مسبقًا. تُستخدم بادئات فريدة
وتُحذف بيانات الاختبار فقط، دون FLUSHDB. أضيفت فحوص الأمان والتسليم عبر
بوابتين وحالات فقد التأكيد والتوافق إلى GitHub Actions؛ حفظ تعريف CI لا يعني
أن تشغيل GitHub نفسه اكتمل. لم يُنفذ اختبار 150 عضوًا أو اختبار أجهزة حقيقية.
