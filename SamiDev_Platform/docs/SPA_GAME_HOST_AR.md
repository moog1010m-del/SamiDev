# تشغيل الألعاب داخل المنصة — 17 أكتوبر 2026

في الويب، فتح الطاولة والانضمام والمشاهدة يتم داخل صفحة المنصة الحالية. يبقى
مشهد اللعبة نفسه أثناء انتظار الخصم ثم بدء المباراة؛ المقعد غير المشغول يستخدم
رسم المقعد الفارغ في المحرك. لا توجد واجهة أو رسالة انتظار إضافية فوق اللعبة.
أدوات إدارة الطاولة متاحة داخل قائمة معلومات الغرفة الحالية.

## التنفيذ

- `platform/game-host.js` ينشئ إطار عرض من نفس المصدر داخل المنصة. الإطار
  يعزل متغيرات المحرك وموارد WebGL عن واجهة المنصة والألعاب الأخرى؛ لا يطلب
  `index.html` خاصًا باللعبة، ولا ينقل المتصفح إلى صفحة لعبة مستقلة.
- `game-bootstrap.js` يجهز الـ Canvas والجسر والملفات بالترتيب المحدد في
  `runtime-games.json`. يُولد الملف الأخير أثناء البناء من تعريفات الألعاب
  الحالية؛ ملفات HTML القديمة باقية للتوافق ومدخلات البناء.
- تهيئة الأصول تستخدم وعدًا مشتركًا لكل نسخة محرك. انتظار الخصم وبدء المباراة
  يعيدان استخدام الصور والـ atlases والمنطق بدل تحميلها وفكها مرتين.
- انتهاء المباراة والعودة من التقييم والخروج تستخدم العقود الحالية: الاستسلام
  المعتمد عند الحاجة، ثم مغادرة الطاولة، ثم إغلاق العرض والعودة للمساحة.
  تُوقف المؤقتات والصوت ويُحرر سياق WebGL عند التخلص من العرض.
- انقطاع النقل يعيد إنشاء عرض اللعبة ويستعيد الغرفة بتذكرة جديدة، مع بقاء
  المنصة. تحديث صفحة المنصة يستعيد مسار المباراة، ويحافظ على وضع المشاهدة.
  تذكرة الدخول ورمز اللاعب لا يُضافان لرابط المنصة.
- في Flutter بقي المتصفح والجسر وخادم الأصول المحلي الحالي. مسارات الألعاب
  تقدم ملف `game-host.html` المشترك من الحزمة بعد التحقق من بصمته وحجمه.
  يستمر التحقق من الأصول والمحركات، وحماية المصدر وسر الخادم المحلي. لم تتغير
  سياسة CSP للسماح بتشغيل المضيف الجديد. يُشعر المشغل Flutter عند اكتمال تحميل
  الجسر حتى يعيد إخفاء أدوات الويب المكررة ويوقف الصوت إذا كانت اللعبة بالخلفية.

## التحقق

التشغيل محلي على بوابة ذاكرة مع GameHost فعلي وChromium باستخدام SwiftShader:

```sh
SAMIDEV_PLAYWRIGHT_MODULE=/path/to/playwright-core/index.mjs python tests/spa_game_host_browser.py
SAMIDEV_SPA_GAMES=pool SAMIDEV_SPA_MOBILE=1 SAMIDEV_PLAYWRIGHT_MODULE=/path/to/playwright-core/index.mjs python tests/spa_game_host_browser.py
SAMIDEV_PLAYWRIGHT_MODULE=/path/to/playwright-core/index.mjs python tests/pool_angle_browser.py
JOIN_SHARED_HOST=1 SAMIDEV_PLAYWRIGHT_MODULE=/path/to/playwright-core/index.mjs python tests/game_join_browser.py
node tests/network_liveness_regression.js
```

اختبار SPA يشغل الألعاب الأربع بحسابين، ويثبت بقاء كائن المنطق والـ Canvas
نفسهما بين الانتظار ودخول الخصم، وبقاء سياق المنصة، وعدم طلب مستند HTML للعبة،
والعودة بعد الاستسلام والتقييم. في البلياردو يفحص أيضًا المشاهدة وتحديثها، وزر
الرجوع وإلغاء الخروج، وانقطاع المقبس واستعادة الغرفة بعد تحديث الصفحة.

اختبار عقد البلياردو يفحص اللعب الفعلي في النمطين، والزوايا متعددة الدورات،
وتطابق النسخ واستعادة الانحراف وإعادة الاتصال. يستخدم المضيف المشترك مع محاكاة
قناة Flutter، ويتحقق من حفظ مسار الغرفة لإعادة التحميل. ينهي المباراة قبل إعادة استخدام
الحسابين؛ تعطيل مهلة إعادة اللعب يقتصر على إعداد الاختبار المحلي.

في Flutter:

```sh
flutter test --no-pub test/runtime_gateway_test.dart test/runtime_policy_test.dart test/chat_bridge_test.dart
flutter analyze --no-pub --no-fatal-infos
```

هذه الاختبارات الثمانية تشمل تشغيل مسارات الألعاب من أصل مشترك موثق، ورفض
الأصول المعدلة، وحماية الوصول المحلي وجسر الشات. بصمات ملفات منطق الألعاب
الأربعة `main.js` بقيت دون تغيير.

عند تعديل تعريفات التشغيل أو أصولها، من مجلد `SamiDev_Platform`:

```sh
python tools/update_ui_build.py
python tools/refresh_integrity.py
python ../SamiDev_Flutter/tool/sync_assets.py
```

الترتيب يولد بيانات التشغيل أولًا، ثم يحدث البصمات، ثم ينسخ الأصول وحجمها
وبصمتها إلى حزمة Flutter. نشر الويب وبناء تطبيق الهاتف عمليتان مستقلتان.

## حدود النتيجة

القياس قبل الإصلاح كشف تهيئتين للأصول لكل لاعب وصور أطالس مكررة في الألعاب
الأربع؛ أزال التغيير هذا التكرار. أزمنة البدء البارد في SwiftShader كانت
متفاوتة ولم تثبت تسريعًا ثابتًا، لذلك لا تعني النتيجة انتهاء كل تقطيع على
الأجهزة الحقيقية. يلزم قياس FPS وزمن البدء على الهاتف والجهاز المستهدفين.
اختبارات المتصفح المحلية واختبارات Flutter لا تعني نشر الويب أو بناء وفحص
APK/IPA جديد على جهاز فعلي.
