# SamiDev V24 — الكيرم وكرة الطاولة

دمج اللعبتين في منصة واحدة: حسابات ومحفظة وغرف ودعوات ومشاهدة مشتركة، وباك إند واحد يوجّه كل غرفة إلى محرك لعبتها. هذه نسخة دمج وتجربة محلية؛ لم تُنشر على سيرفر خارجي.

## التشغيل

المتطلبات: Python 3.12 وNode.js 22 أو أحدث. ثبّت المتطلبات وشغّل المنصة:

```bash
python -m pip install -r backend/requirements.txt
python start_dev.py
```

يمكن تشغيل START_WINDOWS_DEV.bat على Windows. أنشئ حسابًا، واختر مساحة، ثم إنشاء غرفة واختر اللعبة. يشغّل start_dev.py الباك إند ومحرك اللعب ويفتح المنصة. بيانات وضع التطوير محفوظة في الذاكرة وتُفقد عند إيقافه.

| اللعبة | المسار | الخيارات |
| --- | --- | --- |
| الكيرم | /index.html | الخيارات الأصلية، لاعبَان أو أربعة |
| كرة الطاولة | /games/tablesoccer/index.html | تناوب أو متزامن، لاعبَان أو أربعة، 2/3/5 أهداف، حد التمريرات |

## ما تغير

- استبدال مراجع الهوية القديمة في الكود بـSamiDev، بما فيها الجسر العام والدوال المرتبطة به. أسماء دوال اللعب العامة بقيت على معناها لتجنب التعارضات.
- إضافة gameId لإعدادات الغرفة وسجل ألعاب في الباك إند والواجهة، واختيار اللعبة من نافذة إنشاء الغرفة.
- محركان داخل خدمة GameHost نفسها مع حالة مستقلة لكل غرفة. الحسابات والجلسات والخدمات الاجتماعية مشتركة.
- تحويل الانضمام والمشاهدة إلى صفحة اللعبة الصحيحة مع الاحتفاظ برمز إعادة الاتصال داخل جلسة المتصفح.
- توزيع فرق كرة الطاولة 0 و1 ضد 2 و3، والكيرم 0 و2 ضد 1 و3، مع تصحيح اختيار الخصوم في التقييم.
- تنفيذ فيزياء كرة الطاولة والأهداف على السيرفر وحفظ حالة مكتملة بعد التسديدة، ورفض استبدال المواقع من العميل.
- التحقق من الدور والأرقام وشكل الحركة قبل تشغيل المنطق؛ يمنع المسارات المعروفة لتجاوز الدور وتغيير موضع الضارب بحركة مرفوضة في الكيرم.
- إبقاء الغرفة قابلة لإعادة محاولة البدء عند تعطل GameHost مؤقتًا.

## فروق كرة الطاولة

الفريقان الأحمر والأزرق والملعب الافتراضي متاحون بالصور المرفقة. صور الدول والفرق والملاعب المدفوعة غير موجودة في المصدر المرفق، لذلك استُبعدت خياراتها من القوائم.

في الأونلاين تبقى نتيجة التمريرة الفيزيائية بدون التحريك التلقائي اللاحق للكرة والقطع نحو اللاعب. المصدر كان يحركها بالعميل ويرسل الإحداثيات إلى السيرفر. احتساب التمريرات والأهداف مستمر، لكن هذا التحريك التلقائي معطل لمنع تبديل المواقع من العميل.

## الاختبارات الحالية

راجع V24_TEST_REPORT.json لنتائج التنفيذ الفعلية وحدودها. الاختبارات تشمل التسجيل والدخول ورفض الاتصال بدون حساب، ومباريات اللعبتين على الباك إند نفسه، والحركات والأدوار، والمشاهدة وإعادة الاتصال، واستعادة كرة الطاولة بعد فقدان غرفة GameHost، والدعوات ذات الاستخدام الواحد، وتحويل صفحة اللعبة، والأهداف ونهاية المباراة.

```bash
node tests/multigame_runtime.js
python tests/multigame_ws.py
node tests/multigame_routing.js
node tests/browser_multigame_smoke.js carrom
node tests/browser_multigame_smoke.js tablesoccer online
```

فحص الواجهة شغّل JavaScript الأصلي مع جسر رسم وصوت محاكى، وشمل اختيار الفرق وحركة بين السيرفر وعميل كرة الطاولة وتطابق الدور وتسلسل الحركات. ليس اختبارًا بصريًا أو اختبار لمس على جوال. متصفح الاختبار لم يكن مثبتًا وتعذر تنزيله في البيئة. لم تُختبر V24 مع Redis أو Docker أو تحت ضغط إنتاجي.

التقارير الأخرى الموجودة في المشروع تاريخية للإصدارات السابقة ولا تثبت نتائج V24. README السابق محفوظ في docs/legacy/README_V23_AR.md.

## ملاحظات الأمان المتبقية

الدمج لا يغلق تقرير الأمان بالكامل. المسارات التالية من المراجعة السابقة ما زالت تحتاج إصلاحًا واختبارًا قبل الإطلاق العام:

| المرجع | المسار المتبقي |
| --- | --- |
| F04 | سباق تحديث sequence أثناء resync وإضافة الحركة إلى سجل التخزين |
| F05 | استعادة الكيرم من snapshot أقدم مع تجاهل الحركات اللاحقة في GameHost |
| F07 | الحظر لا يبطل اتصال WebSocket المفتوح فورًا |
| F08 | رمز إعادة الاتصال غير مربوط بإحكام بهوية الحساب صاحب المقعد |
| F09 | إمكانية جلوس الحساب نفسه في مقاعد متقابلة واستغلال المكافآت |
| F10 | فحص كلمة المرور المتزامن يحجب حلقة أحداث الباك إند مؤقتًا |

تحسنت المسارات المحددة في F01 وF02 وF03 بالتحقق المسبق من الحركات، وأُصلحت قابلية إعادة محاولة البدء في F06. لم تُنفذ مراجعة أمنية شاملة جديدة لكل المسارات.

## الخدمات والبصمات

docker-compose.yml يربط اللعبتين بنفس المنصة وقاعدة Redis ونقطة Nginx. يحتفظ بالتوزيع الموجود: ثلاث بوابات وثلاث عمليات GameHost، ويمكن تشغيلها كلها على جهاز واحد. كل GameHost يدعم اللعبتين؛ لا يلزم سيرفر مستقل لكل لعبة. مفاتيح الخدمة والدومين وHTTPS تُضبط كما في إعدادات المشروع. لم تحدث عملية نشر أو ترحيل بيانات.

بعد تعديل حزم اللعب عمدًا شغّل:

```bash
python tools/update_game_integrity.py
```

game/samidev-integrity.json يثبت بصمة كل حزمة. ملفات attestation.json الجديدة جرد SHA-256 غير موقّع باسم SamiDev، وليست توقيعات ناشر خارجي.
