# شحن كوينز Plazr عبر Xsolla

تم تجهيز الربط محليًا للمشروع 318587؛ لم يُنشر ولم تُنفذ عملية دفع مع Xsolla.
الدفع معطل افتراضيًا، ووضع الاختبار لا يضيف كوينز قابلة للصرف.

## الباقات

أنشئ هذه المنتجات في كتالوج Xsolla كعناصر افتراضية استهلاكية قابلة للشراء
المتكرر، وليست حزم عملة تقوم Xsolla بفكها إلى SKU آخر. الخادم يحول SKU
إلى رصيد في قاعدة Plazr. فعّل البيع بالدولار فقط لهذه الباقات، دون عروض
أو أسعار إقليمية أو خصومات. أي مبلغ أو عملة مخالفة يرفضهما الخادم.

| SKU | الكوينز | السعر USD |
|---|---:|---:|
| plazr_coins_1000 | 1000 | 1 |
| plazr_coins_5000 | 5000 | 5 |
| plazr_coins_10000 | 10000 | 10 |
| plazr_coins_25000 | 25000 | 25 |
| plazr_coins_50000 | 50000 | 50 |

## إعداد الخادم والحساب

1. في إعدادات المشروع في Xsolla أنشئ Project API key وWebhook secret.
   خزّنهما في بيئة الخادم فقط كـ `XSOLLA_API_KEY` و`XSOLLA_WEBHOOK_SECRET`.
   لا تضعهما في ملفات الواجهة أو Git أو المحادثات العامة.
2. اضبط `XSOLLA_PROJECT_ID=318587` و`XSOLLA_ENABLED=1` و`XSOLLA_SANDBOX=1`.
3. اضبط `XSOLLA_RETURN_URL=https://YOUR_DOMAIN/platform/?topup=return`.
4. فعّل combined webhooks واضبط العنوان:
   `https://YOUR_DOMAIN/api/payments/xsolla/webhook`.
   يستخدم الربط `user_validation` و`order_paid` و`order_canceled`.
   اترك Use public user ID غير مفعّل؛ الهوية هي معرف اللاعب الداخلي.
5. شغّل الخادم مع PostgreSQL. أوضاع الذاكرة وRedis وحده لا تدعم الدفع.
   تمرر إعدادات Docker Compose لكل البوابات الثلاث. حافظ على عنوان IPv4
   الحقيقي للاعب عبر الوكيل الموثوق؛ واجهة Xsolla المستخدمة لا تدعم IPv6.
6. اختبر توقيعًا غير صحيح، لاعبًا غير موجود، شراء كل باقة، تكرار الإشعار،
   والإلغاء. في sandbox تُحفظ الطلبات لأغراض الاختبار دون زيادة الرصيد.
7. بعد اعتماد حساب Xsolla والاتفاقية وضبط الكتالوج، انقل
   `XSOLLA_SANDBOX=0` واختبر شراءً حقيقيًا منخفض القيمة واسترجاعه.

## السلوك والحدود

- ينشئ الخادم توكنًا باستخدام Project ID وProject API key، ويأخذ SKU فقط
  من العميل؛ لا يقبل سعرًا أو معرف لاعب يحدده المتصفح.
- تفتح صفحة Xsolla للدفع، والعودة للمتجر لا تعتبر إثبات دفع.
- يتحقق الخادم من التوقيع على الجسم الخام، المشروع، العملة والمبلغ.
- إضافة الرصيد وسجل الطلب والحركة المالية تتم في معاملة PostgreSQL واحدة.
  سجل الطلب لا تنتهي صلاحيته عند تقليم سجل العرض، ويمنع التكرار بين البوابات.
- إلغاء الطلب يعكس الإضافة مرة واحدة، حتى إن استُهلكت الكوينز؛ يسمح
  الرصيد الداخلي بالسالب لتبقى المديونية محفوظة، ويعرض المتجر صفرًا حتى تسويتها.
  إلغاء يسبق إشعار الدفع يمنع الإضافة اللاحقة لذلك الطلب.
- الاسترجاع الجزئي والـseparate webhooks غير مدعومين بهذا الربط.
  يجب استخدام combined webhooks والاسترجاع الكامل لهذه الباقات.
- الطلبات المالية تحتفظ بمعرف الحساب الداخلي لمنع التكرار والمراجعة بعد
  حذف الحساب؛ يجب تضمين سياسة الاحتفاظ الفعلية قبل تفعيل الشراء العام.
- هذا ربط متجر الويب. لم يُتحقق من إطلاق الدفع الخارجي أو نشره داخل
  تطبيقات iOS وAndroid.
