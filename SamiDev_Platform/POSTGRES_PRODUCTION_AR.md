# التخزين الدائم في PostgreSQL

أصبح PostgreSQL مخزن الحسابات، تجزئات كلمات المرور، الأرصدة، الانتصارات،
المقتنيات والتجهيزات وسجل المتجر والأصدقاء والطلبات والسمعة والتقييمات والبلاغات
وسجل شات المجتمعات. Redis ما زال مطلوبًا لتنسيق غرف اللعب وPub/Sub والجلسات
والتذاكر والحضور وتحديد المعدل. فقدان Redis لا يحذف الحسابات أو الأرصدة، لكنه
ينهي الجلسات وقد يفقد الغرف النشطة؛ يمكن للمستخدمين تسجيل الدخول من جديد.

التخزين يستخدم جدول مستندات JSONB يحافظ على أشكال بيانات V37، بمفتاح أساسي،
وفهرس فريد لأسماء المستخدمين وفهرس لانتهاء الصلاحية. ليس إعادة تصميم كاملة
للنموذج إلى جداول علاقية لكل كيان. عمليات الشراء والتسجيل والمكافآت والسمعة
والصداقة تستخدم معاملات وأقفال PostgreSQL مشتركة بين البوابات؛ المعاملة الفاشلة
تتراجع كاملة. لا تُنفّذ سكربتات Lua في PostgreSQL.

## تشغيل جديد

1. انسخ `.env.example` إلى `.env` واضبط النطاق الحقيقي، ومفتاح GameHost، وكلمة
   مرور قاعدة البيانات، و`SAMIDEV_DATABASE_URL` المتطابق معها. لا تضع الأسرار في Git.
   استخدم ترميز URL للأحرف الخاصة في كلمة مرور رابط الاتصال.
2. من `SamiDev_Platform` شغّل `docker compose up -d --build`.
3. تحقق من `/health`: يجب أن يرجع HTTP 200 وأن تكون `ok` و`dependencies.database`
   و`dependencies.redis` صحيحة. عند تعطل PostgreSQL أو Redis يرجع HTTP 503.

Docker يحتفظ بقاعدة البيانات في `samidev_postgres` ولا ينشر منفذها على المضيف.
احتفظ بحجم Redis القديم؛ لا تستخدم `docker compose down -v` أثناء الترقية.
وضع الإنتاج يرفض الذاكرة أو Redis كمخزن الحسابات، ويرفض بدء التشغيل إذا تعذر
الاتصال بقاعدة البيانات. التطوير المحلي القديم بذاكرة مؤقتة ما زال متاحًا.

## ترحيل تثبيت Redis موجود

توقف خدمة الموقع أثناء النقل. لا تشغّل البوابات الجديدة على قاعدة فارغة قبل
اكتمال النقل، ولا تسمح بكتابات متزامنة من إصدار قديم أو جديد أثناء الترحيل.

1. خذ نسخة احتياطية قابلة للاستعادة من Redis، وسجّل صورة الإصدار القديم وملف
   البيئة. أوقف **كل البوابات وأي عمليات أخرى تكتب الحسابات** وانتظر توقفها.
2. شغّل Redis وPostgreSQL وحدهما: `docker compose up -d redis postgres`.
3. ثبّت متطلبات `backend/requirements.txt` في بيئة Python منفصلة. اضبط
   `SAMIDEV_REDIS_URL` و`SAMIDEV_DATABASE_URL` للوصول إلى القاعدتين. إذا شغّلت
   الأداة على المضيف فاستعمل عناوينه المناسبة، لا أسماء خدمات شبكة Docker.
4. نفّذ أولًا فحصًا بلا كتابة:
   `python tools/migrate_social_to_postgres.py`
5. بعد التحقق من توقف جميع الكتابات وقاعدة PostgreSQL فارغة، نفّذ:
   `python tools/migrate_social_to_postgres.py --apply --offline-confirmed`
   الأداة ترفض حسابات وفهارس مستخدمين غير متطابقة، وترفض الكتابة فوق قاعدة
   غير فارغة. تنقل البيانات في معاملة واحدة وتتحقق من كل قيمة وصلاحيتها
   قبل الالتزام. لا تحذف بيانات المصدر ولا تنقل الجلسات والتذاكر والحضور.
6. شغّل البوابات الجديدة بعد نجاح النقل، وتحقق من تسجيل الدخول والرصيد
   والمقتنيات والأصدقاء والشراء ومن `/health` قبل إعادة فتح الموقع.

للعمل داخل شبكة Docker: شغّل الأداة من حاوية Python مؤقتة على شبكة Compose
مع ربط مجلد المشروع وضبط متغيرات الاتصال بأمان؛ صورة الباك إند لا تتضمن `tools`.

**الرجوع:** قبل إعادة فتح الموقع للكتابة، يمكن الرجوع إلى صورة التطبيق القديمة
وRedis الأصلي. بعد بدء كتابات PostgreSQL، Redis القديم يصبح قديمًا؛ الرجوع
المباشر إليه يفقد التغييرات الجديدة. لا يوجد مزامنة مزدوجة أو نقل عكسي تلقائي.

## تشغيل الإنتاج ومحدودية هذا الباتش

استخدم خدمة PostgreSQL مُدارة أو نسخًا احتياطية منتظمة وWAL/PITR واختبارات
استعادة. اضبط TLS والتحقق من الشهادة عند الاتصال بخدمة خارجية، ومراقبة
`/health` ومساحة الأقراص وحدود الاتصال. العدد الافتراضي 10 اتصالات لكل بوابة
(30 لثلاث بوابات). الإصدار الحالي ينفّذ DDL للتحقق من المخطط عند بدء التشغيل؛
يجب إعطاء حساب التشغيل صلاحيات إعداد المخطط. هذا الباتش لا ينشئ HA أو
نسخًا احتياطية أو شهادة TLS أو خدمة قاعدة بيانات مُدارة تلقائيًا.

تُبقي الترقية حدود سجل المتجر والشات والبلاغات وفترات مطالبات المكافآت والتقييمات
كما كانت في V37؛ هذه سجلات تشغيل محدودة وليست دفتر محاسبة غير قابل للحذف.
تقارير الإصدارات وملفات hashes القديمة في المستودع تخص الحزمة السابقة.

## الاختبارات

استخدم قاعدتي اختبار، واضبط `SAMIDEV_TEST_DATABASE_URL` و`SAMIDEV_TEST_REDIS_URL`:

```sh
python tests/postgres_platform_regression.py
python tests/postgres_migration_regression.py
# بعد تشغيل GameHost وضبط SAMIDEV_GAMEHOST_SERVICE_KEY المطابق له:
python tests/postgres_http_smoke.py
```

الاختبارات تستخدم بادئات/مخططات عشوائية وتزيل بياناتها فقط، ولا تستخدم FLUSHDB.
تختبر التزامن بين بوابتين، الشراء والمكافآت المتكررة، التراجع، فقدان بيانات Redis
المؤقتة، والترحيل والتحقق منه ورفض الاستبدال والتراجع عن الاستيراد الفاشل.
